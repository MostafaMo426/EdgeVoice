01.1 Role of the Application

The Flutter application serves as the Primary Control Plane for the EdgeVoice ecosystem.

  • Control Logic: Directs commands to the hardware via BLE or the cloud API.
  • User Interface: Provides a centralized, intuitive Cyberpunk-themed dashboard for cross-device management.
  • TinyML Bridge: Synchronizes with the Arduino Nano 33 BLE Sense local model execution.
SECTION: PROJECT OVERVIEW

01.2 Dual-Path Communication

Hybrid Connectivity

Ensuring 100% uptime through Local & Remote strategies:

PROXIMITY: Direct BLE (Bluetooth Low Energy) link for ultra-low latency commands.

REMOTE: Global sync via .NET REST API over HTTPS for out-of-home control.

System Flow: User ↔ Flutter ↔ Backend/Hardware

05.0 Application Data Flow

1

User Action

Interaction via UI component (e.g., toggling a Cyan light switch or initiating Mic pulse).

2

Provider Dispatch

UI calls EdgeVoiceVoiceProvider which manages local reactive state variables.

3

Service Execution

Provider calls ApiService (Dio) or BLE service to transmit command to backend/hardware.

4

State Mutation

Upon success, notifyListeners() is triggered, updating the global application state.

5

UI Redraw

Scoped Consumer widgets rebuild instantly to reflect updated device status or AI response.
